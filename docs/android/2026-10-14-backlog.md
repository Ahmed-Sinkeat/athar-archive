# Backlog — owner feedback, 14 October 2026

Source: the owner's review of the benchmark build running on the Redmi against the full
local content. **Sections A–E were implemented on the evening of 14 October (uncommitted,
compiled and unit-tested, NOT yet checked on a device) — see section H.** Section F records
what was done earlier the same day. Order inside each section is the suggested order of work.

## A. Agreed — build next

| # | Item | Notes |
|---|---|---|
| A1 | **Ship the catalog inside the app** | Bundle a snapshot of `index.json` + catalog + tombstones (about 1.1 MB compressed) in assets. First launch imports it through the same signed-chain verification (`SignedRootVerifier`), so the library and title/author/topic search work instantly and offline. Normal sync then updates it. The snapshot must be regenerated for each release; a stale snapshot must never replace a newer applied generation. |
| A2 | **Prefetch several pieces ahead while online** | Today one adjacent piece is prefetched. Raise to about 3–4. **Do not start prefetching during the first open**: show the first page, wait until it is drawn and the reader is idle, then prefetch, so the first open is never slowed. Keep the existing bounds: stop on leave, never pin, honour the cache budget, and no prefetch on low storage. |
