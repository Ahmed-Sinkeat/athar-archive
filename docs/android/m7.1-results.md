# M7.1 interaction quality + performance baseline — interim

Recorded 20 Aug 2026 on branch `android/m7`. **M7.1 is not complete.** The feedback loop
exists and runs, but it is not yet trustworthy, and this records exactly why rather than
publishing numbers that would not survive a second run.

## Implemented

### Theme system

Four defects with one cause: the reader owned a page palette the app knew nothing about.

- `ReaderPalette.Follow` (تلقائي) is added and is now the default. It resolves against the
  app's own resolved theme through `LocalAtharDarkTheme`, not against the system, so
  forcing the app light gives a light page at night. Browsing a near-black catalogue and
  opening a book no longer produces a full-screen cream page.
- `rememberReaderColors` read `AtharTheme.colors.accent`, so a cream page under a dark app
  drew the night accent — pale pink chapter headings, quote rules and play discs on paper.
  Each palette now owns all of its colours.
- Theme is a choice: نظام الجهاز / فاتح / داكن, resolved once in `MainActivity`.
- Font size, spacing and palette were a `remember` inside each reader, in two independent
  copies. They now live in `AppearanceStore` on SharedPreferences and are hoisted through
  `MainActivity`, so they survive rotation and process death and both readers agree.

الإعدادات loses two dead rows and gains one live one — المظهر والقراءة — over a live
preview of the page in the palette and size being chosen.

### Interaction defects removed

Each was found by using an APK, not by reading the code.

| Defect | Effect |
|---|---|
| `AudioRow` had no click action | tapping a recording's title did nothing; the only list in the app that ignored the obvious gesture |
| No save or download control on `AudioRow` | قائمتي filters on `audio.saved` and nothing could set it, so the tab was permanently empty |
| `PlayerScreen` lacked `navigationBarsPadding()` | the queue ran under the system nav buttons and its last row could not be tapped |
| Three player tiles passed `weight` to a wrapper, not to `ActionTile` | tiles shrink-wrapped their labels; السرعة rendered half the width of تكرار |
| `ActiveChips` was a non-scrolling `Row` | scope + two sources + an author ran past the edge: filters applied that could not be seen or removed |
| Reader printed `chapterTitle` under an identical `bookTitle` | a single-chapter work showed its name twice, six points apart |

Locked by `app/src/androidTest/.../InteractionQualityTest.kt` — three checks covering
audio-row reachability, the save/download controls, and that المظهر والقراءة opens a
screen offering تلقائي.

### Benchmark harness

`:benchmark` targeted `:m0` since M0 and was measuring a harness that no longer resembles
the app. It now targets `:app`, and `MainActivity` publishes Compose test tags as
resource-ids so UiAutomator can drive real screens.

Five benchmarks map to §17: `coldStart`, `tabChanges`, `booksFling`, `readerFling`,
`searchTyping`.

## Harness faults found and fixed

| Fault | Symptom | Fix |
|---|---|---|
| Suite exceeded the run cap | 2 of 5 benchmarks never executed | iterations 8 → 5, run uncapped |
| `UiObject2.fling()` needs `scrollable="true"`, which Compose lists do not advertise | reader fling measured **one frame** | coordinate swipes via `UiDevice.swipe` |
| Benchmark variant is release-like and non-debuggable with no `<profileable android:shell="true"/>` | `frameCount` only, never durations | benchmark-only source-set manifest |
| `androidx.profileinstaller` absent from the app | cold start could not run at all | added to `:app` |

## Open blockers

**Cold start cannot be measured on this phone.** After adding `profileinstaller` and
confirming `ProfileInstallReceiver` and `profileable` are both in the packaged manifest,
`StartupBenchmark` still fails with `The DROP_SHADER_CACHE broadcast was not received`.
The device is a Redmi 12 on HyperOS, which restricts broadcasts to stopped apps. This is
the wrong target regardless: §17 specifies a low-memory API 26 profile — a 2 GB emulator,
not a phone. **Next step: provision that emulator profile and make it the budget target,
keeping the phone for real-feel checks only.**

**Frame timings are still absent and frame counts are not repeatable.** Only `frameCount`
is reported; no `frameDurationCpuMs` or `frameOverrunMs`. Worse, `readerFling` measured
107 frames on one run and 1 on the next with no change to the benchmark, which means the
setup step is not reliably reaching the reader. Until a benchmark returns the same number
twice, none of its numbers should be quoted.

**The catalogue holds one book.** `booksFling` reports one frame because there is nothing
to scroll, and it will keep doing so however the harness is fixed. The §17 list-scroll
budget cannot be exercised until the catalogue carries more than the §16 slice.
